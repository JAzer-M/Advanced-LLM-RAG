# QASPER新论文配对评测：修复、结果与代价

2026-10-25（Asia/Shanghai）。**16篇新论文、52题、原版/修正版三模式共312条生成及312条判分记录均已完成。** 原版为本地提交`54fa038`；新论文排除旧轮全部15篇，旧52题只用于开发诊断。数据、源码、失败和模型切换均保留。

**本轮改善最明确的是Agent的交付与模型判分：无交付失败12→0，判分correct 26→36，生成token约增1%。Auto较旧版少用35.4%生成token，但correct仍为34/52，完整答案F1基本持平。RAG完整答案F1也基本持平。首段F1的上升不能当作全部解释与引文都正确。**

当前修正版Agent仅比同版RAG多1条模型correct（36对35），生成token约为RAG的4.93倍；Auto为1.91倍。因此，本轮没有证明Agent/Auto普遍优于RAG，也不能把旧Agent的修复收益当作Agent相对RAG的净收益。

## 1. 测了什么

[冻结协议](protocol.md)、[机器协议及源码哈希](protocol.json)、[冻结题集](frozen_sample.json)。QASPER v0.3测试集按种子20261025整篇抽样至至少50题，实际16篇52题；当前arXiv PDF生成独立版本`qasper-holdout-20261025`，1459段、384维。PDF可能与QASPER全文版本不同。

两版接收相同题名/arXiv题头和原问题，同库、每路候选120、初选Top10、最多2轮规则补查，rewrite/HyDE及arXiv工具关闭。保留原检索锚点、局部证据和身份锚点；Agent可在既定3行动、最多32段/24000字符内扩展上下文。Gold不进入生成、规划或复核提示。

修正版增加：明确论文来源范围与检索正文分离；范围贯穿Dense/BM25、规则补查、Agent搜索与邻段；有限PDF断行引文兼容；唯一题头的需求引文绑定；明确回答语言和独立结论段；本地Agent失败时共享原11请求预算的RAG后备交付。代码、原文件结构与调用方式保持，未增加运行依赖。[原版快照](baseline_source/sha256.json) · [修正版快照](revised_source/sha256.json)

这是一组组合改动的配对对照，不能把所有差异单独归因于某一模块。冻结后未据新题输出改动生产代码。前116条顺序执行，后续同题两版本独立进程并行，条件与哈希见[调度记录](execution_transition.json)。耗时受缓存、执行顺序和并发影响，不作跨模式纯速度结论。

## 2. 主结果：同一新题集、失败保留分母

F1按0—100显示，**不是准确率百分比**。主指标是完整答案Answer F1；首段F1取实际第一个独立段落，模型未分段时就仍是整段。两版均使用同一拒答/短答转换，未按Gold抽取预测内容。模型correct分母均为52；failed生成机械计incorrect，不再付费判分。程序completed和review_passed都不是正确性标签。

| 模式 | 完整答案F1 原→新 | 首段F1 原→新 | 模型correct 原→新 | 正常/降级/失败 原→新 | 生成token变化 |
| --- | ---: | ---: | ---: | --- | ---: |
| RAG | 19.67 → 20.00 | 19.59 → 30.05 | 32 → 35 | 52/0/0 → 52/0/0 | -0.6% |
| Agent | 16.28 → 20.60 | 15.27 → 31.13 | 26 → 36 | 40/0/12 → 42/10/0 | +1.0% |
| Auto | 19.62 → 19.49 | 18.15 → 29.88 | 34 → 34 | 46/5/1 → 50/1/1 | -35.4% |

模型判分的correct/partial/incorrect分别为：原版RAG 32/8/12、Agent 26/8/18、Auto 34/9/9；修正版RAG 35/9/8、Agent 36/10/6、Auto 34/9/9。全部判分记录完成，其中298次真实判分、14条失败生成按规则处理。判分使用旧轮固定JUDGE提示，输入问题、参考答案和完整输出，不传版本标签；未逐条读取全文，所以无法证明附带事实或引文都被原文支持。

52题的六条生成均使用同一请求模型：26题`cn:glm-5.3-flash`，26题`cn:glm-5.3`，无题内混用。全部实际判分请求使用`cn:glm-5.3`，故原Flash题的判分与作答模型不匹配；但同一题的两版使用相同作答模型，双方也使用相同判分模型。逐组不匹配数量和报告模型见[汇总](summary.json)，不能称单模型52题实验或独立人工准确率。[逐题分数](scores/per_question.json) · [分生成模型结果](per_model_summary.json)

完整答案F1与原始Evidence F1、首段Answer F1均经官方脚本复算，无缺失预测、无超过1e-12的差异。[官方输出](scores/official_evaluator.json) · [最终核验](verification.json)。这只证明给定输出转换后的计算一致，不证明转换或证据映射在所有语义上正确。

### 差值与不确定性

按论文簇bootstrap 5000次，单位为F1点/模型correct比例的百分点。以下均是52道请求模型匹配的配对；模型判分比较也使用双方相同的判分模型，失败生成的规则标签保留。

| 模式 | 完整F1差值 | 95%区间 | 模型correct比例差值 | 95%区间 |
| --- | ---: | --- | ---: | --- |
| rag | 0.33 | [-6.34, 6.71] | 5.77 | [-6.67, 17.39] |
| agent | 4.31 | [-2.45, 11.40] | 19.23 | [4.17, 31.82] |
| auto | -0.12 | [-6.14, 6.45] | 0.00 | [-11.76, 10.00] |

完整答案F1三个区间均含0；模型判分仅Agent的区间为正。这支持“在本次题集和判分规则下，旧Agent有改善”，不支持普遍准确率结论。作为事后敏感性分析，剔除有API错误的模式/问题配对后，Agent为26→35 correct（51题），Auto为34→34（51题）；原计划分母与主表没有被改写。[敏感性分析](sensitivity_no_api_errors.json)

旧拒答启发式下，本组Auto的F1会是17.69→19.49；统一新口径后则是19.62→19.49。不能挑前者来宣称Auto回答质量上升。旧10月24日的14.83/14.81/21.39来自另一组论文、模型与冻结转换，原分数保留，不能跨题集直接归因。

## 3. 检索、引用与已确认的退步

| 模式 | 原始Evidence F1 原→新 | 仅NFKC/空白归一F1 原→新 | 最终上下文命中至少一段Gold |
| --- | ---: | ---: | ---: |
| rag | 34.50 → 34.16 | 37.06 → 38.01 | 28/49 → 35/49 |
| agent | 41.58 → 43.07 | 43.50 → 46.28 | 33/49 → 37/49 |
| auto | 40.85 → 36.65 | 44.70 → 38.36 | 32/49 → 36/49 |

上下文命中包括已登记的身份锚点和Agent扩展，**不是独立Top10的Precision/Recall**。初选命中另保留在逐题分数；实际引用段落F1和上下文存在Gold是不同指标。Auto上下文命中增加而引用Evidence F1下降，说明选到原文不等于正确使用它。

新49道有正文Gold的题中，按冻结近似映射只有44题能对齐到Gold片段；另外5题仍可能在PDF里含有关键事实，不能说“库里没有”。公式、数字空格、断词、引用占位符和段落切分会影响0.5阈值映射。[可用性诊断](diagnostics/new_gold_availability.json) · [五题原文比对](diagnostics/new_unaligned_gold.json)

按固定顺序取四篇首题、两版三模式共24份输出做来源核对，见[完整抽查](manual_review.md)。这是Codex逐段核对，不是独立人工准确率样本。主要发现：

- 架构题中修正版补到了logistic regression，但Auto把前人方法的两套RNN写成本方法；本方法实际用单个双向RNN。
- CCPC1.0数据来源题中，原版RAG/Auto正确，修正版三模式拒答。Gold段落仍在候选池，却被排第68位，属于真实排序/选择退步。
- 金融知识题的参考标注同时有Yes和No；原版引用外部金融语料回答Yes，修正版Auto以未建模公司/aspect推出No，该否定推理没有由引用建立。新样本共3题有互相矛盾的二元参考答案。
- 修正版仍可能不分独立短段，全缺失模板也可能带出中文缺口；明确语言/首段提示没有覆盖所有路径。

这些反例没有通过改答案、调阈值或重跑来消除。旧题离线诊断也不是新质量证据：五道有Gold的缺陷题Top10命中2→4，但MAP .4000→.3333；默认Top10保持。[前期分析与完整诊断](analysis_findings.md)

## 4. Agent回退并不等于原循环全部修好

原Agent的12条failed中，修正版9条completed、3条degraded；同时7条旧completed转为新degraded。因此新Agent的10条降级并非都在修复同一组旧失败。回退只用初检原文、最多新生成一次及一次引用修复，共享原11次上限；保留原Agent日志，后备答案未通过Agent语义复核。[逐题状态转移](status_transitions.json)

Auto的5条旧degraded均转completed，但有1条旧completed转degraded；两版各1条failed是同题的网关故障。状态改善与模型判分、事实支持分别解释。

## 5. 反代故障与模型使用

按照用户顺序先用GLM 5.3 Flash；第26题的两版Auto分别遇HTTP502/503，保存失败后统一换GLM 5.3，完成余下生成及判分。原因不能仅凭5xx证实为配额耗尽。另有1条旧Agent收到stop但空正文，客户端异常没有保留usage，失败原样保留，没有被当作同一类网关配额故障。[三条API失败](failed_api_calls.json) · [模型切换记录](supervision.json)

本轮读取21个可用模型ID，后续队列包含DS 4.1 Flash及MiniMax、Kimi、MiMo、Step等文本候选，见[实际列表](model_inventory.json)。本轮未用到这些后续模型，不能宣称它们已现场验收。模型配置按进程固定，未改写网页/本机保存的模型设置；反代报告的模型别名也不能证明后端权重身份。
