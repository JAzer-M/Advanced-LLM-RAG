# P3.1 arXiv只读工具：实现、实测与剩余边界

2026-10-22。用户要求修复反馈状态后进入P3，并明确选择先接arXiv论文。本轮先完成两个独立工具，接入Agent/外部引用链属于下一小步；P3整体尚未完成。

## 工具及作用

`src/arxiv_tools.py`新增普通函数`search_arxiv(query, output_dir, limit=3)`与`read_arxiv_paper(arxiv_id, output_dir, two_columns=False)`。

搜索定位论文，返回带版本ID、标题、作者、摘要、网址及原始Atom；元数据不作为回答证据。读取要求现代固定版本ID，下载同一版本PDF，复用原`pdf_loader.load_pdf()`提取来源/页码/章节/原文，附独立`evidence_id`、PDF哈希和获取记录。它不冒充本地位置chunk_id，不修改知识库、激活指针或旧论文，也不生成回答。[设计与官方接口依据](design.md)

每调用使用新的空输出目录；搜索最多5条、检索式最多500字符；PDF最多20MiB/60页/160000提取字符。超限/空文本/非PDF/版本路径改变等显式失败，不静默截取；HTTP及解析失败保存，网络不自动重试。当前只支持现代版本ID，双栏是显式开关，不声称通用无损版面解析。

请求单进程串行，相邻开始至少3.1秒、超时30秒；跨进程/设备需统一遵守来源限制。新增直接依赖声明`certifi`，环境中原已安装，无安装或升级；SSL默认信任保留，并追加其根证书，证书和主机名验证保持启用。没有引入SDK、框架或新生产CLI。

## 离线验收与文件保护

新增10项工具测试，HTTP替身、内存生成PDF，但解析和落盘走真实代码。覆盖版本与URL、原始响应和哈希、实际原文及页码、空搜索、错误题录、重复ID、HTTP失败保存/不重跑、非PDF/变更版本/异常来源、字节/页数/正文预算、串行速率及TLS验证开启。初版测试曾因构造重复条目时XML不合法而报错，修正夹具后通过；首次失败日志保留。

反馈修复新增11项，原251+11+10=272项既有与新测试全部通过，网络连接被禁用、尝试0。最后TLS修改后再次全套通过，见[最终测试摘要](offline_test_summary_final.json)和[原始输出](tests_final_tls.log)。此前全套272项与CA专项10项的记录也保留，不重复累计为测试数量。

最终源码、配对知识库/原有文件、实验成绩与失败、Git差异、链接及原文身份检查见[核验](verification.json)。旧固定RAG、main、检索与回答实现保持，新增arXiv工具不改变三模式行为。没有提交或推送。

## 下一步P3.2

接入最小闭环：本地资料确有缺口时选择联网搜索/读取 → 将外部原文和来源登记进证据/引用表 → 沿用需求范围、连续引文和回答复核 → 记录公网/模型预算及停止原因。资料不足仍应明确拒答，长期复用再另建知识库版本。

随后冻结新题验证需要联网、不需联网、找错论文、服务失败、引用支持和成本。当前只证明独立工具能检索/下载/提取，不能宣称Agent已经自动联网、Mamba问题已经正确回答或P3质量收益通过。
