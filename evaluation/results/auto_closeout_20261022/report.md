# Auto 实现与三路径对照收尾

2026-10-22。Auto已实现，本轮8题对照完成并保留失败；239项离线测试通过。**功能实现与本轮实验收尾，稳定性/质量收益验收未通过。** P3没有实施。本报告不替换历史P2.5的12题结果，也不把3题开发修复并入新题分数。

## 设计及每项功能的作用

处理顺序是：共同初检 → 模型提取本题需求 → 模型检查原文支持 → 本地校验 → direct / agent / stop。

- 先有初检：让选择依据包含真实证据。短问题未必有出处，长问题也可能一次检索齐全。
- 复用原规划/判断：只有全部需求supported且提出answer时直答；有可补缺口才调用搜索或邻段；无法建立事实时说明不足。没有另加纯问题分类器。
- direct复用原RAG生成和最多一次引用修复：省去额外答案复核，但仍可能生成不完整内容，不能视作语义校验通过。
- 在首次工具前暂停，再同协议继续：规划、判断、证据及已用修正额度都留在原账本，不重新付费规划、不重置6次决策和一次校验修正预算。
- 路由先写routing.json：保存理由、需求状态、原行动及门控调用数，便于查错和算成本。
- CLI默认auto，Python函数默认rag以兼容旧评估；显式rag/agent仍可使用。Auto/Agent用八篇库，不切换三篇激活指针。

最多1次分解+6次决策+4次回答=11请求，3次工具行动，32段/24000字符证据；网络或截断不自动重试，失败不切其他路径。详细功能表、流程图、文件入口和命令见[设计说明](design.md)。

## 如何验证

先保存2832个现有文件哈希及源码基线；新增9项Auto行为测试，先失败后通过，再运行全部239项回归。测试覆盖direct、工具前暂停/续接、stop、共享修正预算、引用修复及修复后仍失败、CLI默认值；既有RAG和Agent入口测试保留。[最终239项回归](tests_final.log)阻断socket网络，网络尝试0；三次本地失败由[离线复现](failure_replay.json)重现，不请求模型、不覆盖真实输出。

随后冻结3单篇、3跨篇、2不可答新题，区分必答和补充，13处Gold引文核对原PDF。每题只实际初检一次，分别跑RAG、固定Agent、Auto；Agent/Auto走生产main审计入口，驱动只替换重复初检。旧答案、Gold、评分点、原分解不进入Agent/Auto。全程未根据新题结果调参、改提示或换失败题。

因此，这测的是“同一真实初检后接不同处理层”的效果，**不是三次独立端到端CLI实验**。同库、同助手出题/审阅、小样本、每题一次；不证明未见语料泛化或统计显著性。[冻结规则](review_protocol.md)、[问题](questions_frozen.json)、[原始调用](actual_chat_calls.json)、[离线复算脚本](summarize.py)。

Agent严格标准额外扣除a02的补充公式解释：必答参数和顺序正确，但把完整归一化响应描述为求和所得。原PDF显示应除以含平方和的归一化因子；原分块未提取完整公式。[逐题原文审阅](manual_review.md)公开这一保守判断。若只要求必答点完整，Agent为7/8；主要的Auto两题无交付结论不受此判断影响。

固定Agent的a05还混入不必要的[3]（ColBERT）引用，同组[9]实际支持DPR事实，记为引用冗余，未当作事实无依据。补充内容不因省略而扣分；添加错误/支撑不足的事实仍按既定标准审阅。

## 路由是否合理

先读每题共享初检并保存[路由参考](route_reference.json)，再查看Auto最终答案；同一审阅者知道题目和运行进度，因此不声称盲评。6道可答题初检均已包含完整必答证据，主标签均为direct；2道不可答题主标签stop。a08存在原论文，初检没有成本/能耗，先搜索确认缺失也合理，这个替代标签在看最终答案前保存。

实际为 **4 direct、1 agent、1 stop、2 failed**。主标签一致5/8；计入预先记录的a08合理替代为6/8；剩余2题未完成决策，不从分母剔除。4次直答证据均足够，1次补查用于验证缺失测量，没有把缺失数字猜出来。

a08的固定Agent和Auto均先search、再read_neighbors，随后model_stop；最终证据分别16段/6882字符、15段/6511字符，回答阶段0请求、本地说明不足。Auto真实执行了工具分支，原计划只实际请求一次，暂停续接未重复规划。本批没有“初检缺关键事实、工具补齐后答对”的可答正例；不能据此宣称补查提高了回答准确率。

## 失败原因与后续优先级

1. **P1，正常问题无交付：排版归一化误阻塞。** a03 Auto正确找到了1387和数值，但把`Arc- Challenge`写为`Arc-Challenge`，初次与唯一修正都被连续原句校验拒绝。后续应区分可验证PDF断行规范化和真正改写/拼接；不能直接放开逐字证据检查。
2. **P1，正常问题无交付：复杂并列主体绑定不足。** a04的`For A ... and for B ..., ... in each`不能被当前只处理紧邻主体的投影规则表示，Agent/Auto均失败。应以原句跨度和各自条件为边界改进绑定，避免把别的方法或任务条件搬移进来。
3. **P1，附加断言和引用精度。** a02的公式说明支撑不足，a05有引用冗余。答案复核自报pass仍不能代替原文审阅；完整性优先级不要求额外公式背景，却仍要求已经写出的事实准确。

按本次“实现Auto、做一次对照后收尾”的范围停止；上述作为下一轮待办，不在新题上反复调到漂亮分数。**本轮不能声称Auto/Agent优于RAG，也不建议用增加工具或P3扩展代替当前稳定性修复。** 项目已具备需求驱动行动、真实工具反馈、预算约束、自动分支和可复核量化证据，质量收益仍未成立。

当前运行方式、优先级和下一步见[项目PROGRESS](../../../PROGRESS.md)，文件保护与冻结核对见[最终核验](verification.json)。新题若用于后续修复即转为开发集；未来比较应另建独立题集，包含自然分布中的初检不足正例，保持成本与失败分母，不把本批调试成绩再称为留出表现。
