# Auto 收尾：运行前冻结的三路径对照

本轮为8道新问题：3单篇、3跨篇、2不可答。问题作者和审阅者均为本代码助手，语料仍是已有八篇论文，部分概念与历史题相近。因此这是同库小样本检验，不是第三方盲评、未见语料测试或总体显著性证明。首次调用后不改题、不调提示、不把失败题替换为开发题。

## 比较边界

- RAG：生产 main 的固定流程；候选120、Top-10、最多两轮规则补查，rewrite/HyDE关闭；一次分解、一次回答，最多一次引用修复。
- 固定 Agent：同一初检之后，无条件进入现有需求规划、证据判断、最多3次工具行动和回答复核。决策最多6次请求，回答最多4次。
- Auto：同一初检之后，同样先规划需求、判断证据；全部必答需求有证据则直接使用原RAG生成和引用修复；存在可补缺口则从原判断状态继续工具循环；无法补足则停止。直接回答不执行Agent答案复核。路由判断不是免费分类器。
- 为隔离路由影响，每题共享一次真实RAG初检（包括规则补查）。Agent/Auto均通过生产 main 的审计入口调用，实验驱动只用已保存初检替换重复检索；仍执行真实 _answer_with_agent、决策、工具和回答函数。这个驱动不等于三次独立的端到端CLI运行。
- 初检白名单只包含 query、knowledge_base、retrieval_diagnostics、selected_ids、context、ledger。RAG答案、分解输出、Gold、评分点不会传入Agent/Auto；没有跨路径的决策/回答响应复用。
- 同一API公开设置、知识库、预加载CPU模型。每题实际最多23次请求：共享初检1、RAG生成/修复2、Agent新增10、Auto新增10；全轮最多184次。独立路径归因各计共享初检一次，实际总账只计一次。网络失败和截断不自动重试。
- 请求前记账，精确续接只复用同题、同阶段、同提示和同设置的已完成响应。失败/进行中请求不重试；服务连接/限流故障终止批次。终止和未运行题保留计划分母。
- 耗时为预加载模型后的顺序单次运行。路径耗时=共享初检+该路径增量，排除其他路径生成时间；模型初载另记。不能据此声称冷启动、并发或P95性能。

## 运行前评分

每题分别冻结 required_points（用户明确所问的必要信息）和 supplementary_points（背景信息，不进入严格通过分母）。不要求额外展开未问的定义或历史背景。

1. 逐条记录 covered / partial / missing / wrong，只有 covered 计1。可答6题同时报告核心覆盖 micro、macro；失败或没有交付答案计0。
2. 严格通过要求必要点全覆盖，无实质错误、无无依据新增事实，关键引用确实支持相邻断言。系统自报review_passed或completed不代替人工核对。
3. 不可答2题必须明确当前语料无法确定所问事实，不猜数字。分别记录正确拒答和可答题过度拒答。
4. 证据审阅使用原始PDF/标准分块，核对主体、数值、条件、引用；引用编号的程序检查只证明格式。
5. 按题保留三路径成败、核心点、引用缺口和实际答案。主要分母为计划8题，成功子集可另报。不得拼接历史12题或3题修复结果。

## 路由审阅

在查看该题Auto最终输出之前，审阅共享初检原文，并冻结该题应有路由标签：direct（已足够）、agent（库内存在缺口证据且值得补查）、stop（库内无法建立必要事实）。Gold只帮助定位候选来源，不能用“是否命中指定Gold ID”代替对实际初检的语义审阅。

保存审阅顺序记录。若同一审阅者已看到中间运行日志，明确不声称盲评。记录误直答（应补查却direct）、不必要补查（初检足够却agent）、正确升级、正确停止、决策失败。路由正确不代表生成一定正确；direct能否省成本也要与质量共同看。

## 成本、检索及收尾

报告实际HTTP POST、客户端尝试、失败、重试、finish_reason、prompt/completion/total tokens和usage缺失；路径分别分摊初检，真实总账去重。报告工具行动、停止原因、上下文条数/字符数、各题耗时和均值/中位数。没有核验单价则不换算货币。

共享Top-10另算Precision、nP、Recall、MAP、MRR（只统计有Gold的6题）。Agent追加证据的召回与长度另列，不伪称同预算Recall@10提升；不另跑Top-20或其他候选预算。

收尾的完成条件是：Auto行为可复现、原预算不重置、离线回归通过、三路径冻结对照和失败证据保留、文档反映真实收益与局限。即使Agent没有胜过RAG也如实结束P2，不根据本轮结果继续针对同题优化。P3本轮不实施。
