# h06: How do DCNN and VGG distribute training across multiple GPUs, and how do the GPUs exchange information in each scheme?

## 回答

DCNN 的做法是把网络分摊到两块 GPU 上：每块 GPU 放置一半的 kernel（或神经元），并且 GPU 之间只在某些层进行通信（[3]）。例如，第 3 层的 kernel 接收第 2 层所有 kernel map 的输入，但第 4 层的 kernel 只接收位于同一 GPU 上的第 3 层 kernel map 的输入（[3]）。这种划分方式在多 GPU 上的具体表现是：一块 GPU 运行图中上部的层部件，另一块运行下部的层部件，GPU 仅在特定层通信（[5]）。

VGG 采用数据并行：将每批训练图像拆分为若干 GPU batch，在各 GPU 上并行处理；各 GPU 计算出梯度后对其取平均，得到完整 batch 的梯度（[1]）。其梯度计算在 GPU 间是同步的，因此结果与单 GPU 训练完全相同（[1]）。

### [1] VGG.pdf, p.5 (chunk 273)

Multi-GPU training exploits data parallelism, and is carried out by splitting each batch of training images into several GPU batches, processed in parallel on each GPU. After the GPU batch gradients are computed, they are averaged to obtain the gradient of the full batch. Gradient computation is synchronous across the GPUs, so the result is exactly the same as when training on a single GPU.

### [2] DCNN.pdf, p.3 (chunk 138)

4.2. Training on multiple GPUs A single GTX 580 GPU has only 3GB of memory, which limits the maximum size of the networks that can be trained on it. It turns out that 1.2 million training examples are enough to train networks which are too big to fit on one GPU. Therefore we spread the net across two GPUs. Current GPUs are particularly well-suited to cross-GPU parallelization, as they are able to read from and write to one another’s mem- ory directly, without going through host machine memory.

### [3] DCNN.pdf, p.3 (chunk 139)

The parallelization scheme that we employ essentially puts half of the kernels (or neurons) on each GPU, with one addi- tional trick: the GPUs communicate only in certain layers. This means that, for example, the kernels of layer 3 take input from all kernel maps in layer 2. However, kernels in layer 4 take input only from those kernel maps in layer 3 which reside on the same GPU.
