# P1 小规模留出评测 v1：执行与结果日志

日期：2026-10-20（Asia/Shanghai）。运行前冻结于 `2026-10-20T02:48:49.660710+00:00`，真实运行完成于 `2026-10-20T02:59:20.891454+00:00`。本轮按用户批准的方案完成评测并保留瑕疵；不以分数达到门槛作为收尾条件。

本轮建立了 12 道新题的可审阅基线：10 道可答题的 **P@10=.1800、nP@10=.7200、Recall@10=.7900**；按冻结标准的核心点完整覆盖宏平均 **70.0%**，严格完整通过 **4/10**。两道资料边界题均正确拒答，其中一题附带数值没有引用，因此包含引用要求的总体严格通过为 **5/12**。这些是新测量结果，本轮没有调参，不解释为相对旧题集的性能提升。

## 1. 具体执行了什么

1. 核对八篇论文、当前知识库、旧 46 题与最新实验。按用户澄清，**P0 基础导入已完成**：从原三篇增加的五篇已进入独立及合并库；通用去重、完整增量生命周期等增强延期，不重做导入、不继续大量下载。
2. 新建 4 道单篇、6 道跨篇、2 道不可答英文题，逐题记录与旧题知识目标的区别；既有 46 题（42 道可答题）与 Gold 保留。本次是同一已知语料上的开发流程留出集，作者和审阅者均为本助手，不是第三方盲评、未见论文泛化或预训练未见证明。
3. 在第一次模型调用前，冻结题目、原文 Gold、核心评分点与规则。25 条 Gold chunk 的引文及两条拒答边界引文均核对到本地 PDF 页；同时保存 120 页/8 PDF 清单、Mamba 全文缺席扫描和 1,277 项旧源码/数据/实验文件哈希。
4. 12 题各运行一次当前真实 main：全新 API 分解、真实 Dense/BM25/RRF/BGE 检索重排、现有来源补查、真实 API 最终回答。没有使用固定答案或 oracle Gold。运行时仅向 main 传问题字符串与固定版本，Gold/核心点/评审文件都不传给模型；题型也不改变检索/生成行为。
5. 从**同一批主流程的 selected_ids**离线复算全部检索指标；逐题人工阅读答案和引用，对照冻结核心点，记录漏答、拒答、重要断言支撑与调用成本。额外只读记录实际初始候选/全局排序 ID，以区分候选漏召和最终选择遗漏；未改候选或排序。

## 7. 实际成本和验证

实际 **24个chat POST**：12次新分解、12次新最终生成；全部finish_reason=stop，失败/自动重试/引用修复均为0，未触及36次上限。代理报告输入 **32,080**、输出 **2,476**、合计 **34,556 token**；不据此推测未核实的金额。

共享CPU模型初载后的整轮耗时 **611.583秒（约10分12秒）**，单题9.86～135.54秒；API请求计时合计52.674秒，其余包含本机模型检索重排、加载和日志等，未做细项profile。该小样本顺序运行不是冷启动、并发或P95性能基准。Python3.11.9；依赖版本在[调用成本明细](api_usage_summary.json)。

- 1,277项旧输入哈希运行前后相同，包含生产源码、配对知识库、原PDF、激活指针、旧题/Gold和旧结果。本次发布时仅对原有README/PROGRESS作进度说明更新，新增题集、标准和日志；发布核对另存。
- 用原项目纯Gold映射函数重新核对25条Gold，并以独立公式重算10题×5项指标；原始selected_ids与citation_registry前10条一致，所有引用文本/source/page与当前chunk匹配。
- 冻结文件hash在运行后仍匹配，冻结时间早于首个chat；24条请求逐次审计与逐题记录相互一致，选项也与冻结配置相同。
- 新增脚本通过语法检查。生产代码未改，79项unittest是历史通过记录，本轮未重复运行，未冒充本轮测试。
- 私有API配置/凭证不进入产物。既有模型使用本机离线缓存，未为本轮重新下载或对缓存权重做全量新哈希。

## 8. 当前阶段与下一步

**P0基础导入已完成；固定RAG收尾已完成；本轮P1小规模留出基线已完成。** 完成的是一次可核验评测，不是宣称质量全部通过。现存细节缺失、引用缺口与比较保留措辞按用户决定留档。
