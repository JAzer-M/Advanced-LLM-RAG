# 反馈状态修复与P3前置收尾

2026-10-22。用户要求先修复反馈状态问题，随后进入P3，并明确P3先接arXiv论文。保持普通函数/字典/列表和原调用预算；本轮不重算旧12/8题分数，不为已知h10重复付费。

## 复现与最小修复

新增回归首先在旧源码稳定复现：h10的Self-RAG侧经一次真实旧修正后已supported，工具只新增RAG论文原文，反馈仍将Self-RAG标partial/空gap，触发`The one decision-repair budget was already used`。首次单测红灯和9项初版边界回归的4失败/1错误均保存在repro_red.log/tests_red.log。随后将真实首次搜索/反馈前缀最小化，补充两个主体的小型跨论文夹具。

按三个可证伪判断推进：全量重查是否引入无关回退；保留状态是否会遮蔽新反证；问题是否能在不放宽partial契约的情况下消除。修复仅改agent.py的assess_evidence/run_diagnostics，并新增feedback_scope函数。

- 每次真实新增原文后，始终复查所有未完成需求。
- 已supported需求若收到同源新段，或新段标题/正文明确提及其主体，也重新检查，允许合法conflicting/partial重新打开。
- 其余已supported需求保留上一份已校验状态及原文引文，模型只更新本轮复查ID。提示中带原文和明确复查/保留清单，审计保存feedback_scope。
- 模型额外返回保留项时，其更新不应用；原始响应留在调用日志，保留的是旧已校验对象，不把无效partial改为supported。未知/重复/缺失ID仍拒绝。
- 合并后仍执行原validate_assessment的完整主体、来源、连续引文、状态和行动校验。被复查项的空gap、伪引文和跨主体内容依然失败。
- 循环、单步、行动改选、反馈修正都传递同一状态；仍共用一次修正额度，决策最多6、工具最多3，未重置预算或修改检索/main/回答提示。

同源/显式主体是保守相关性规则，不是通用语义冲突识别。新证据若既不来自已引用来源又未直接提及主体，隐含反证可能漏触发；当前独立新题总体收益仍未验证，原始误判也不能靠状态保留自动纠正。

## 验证与范围

新增11项测试，全套先262项通过；加入P3.1工具后最终272项通过，网络尝试0。覆盖旧h10前缀、真实循环/单步、只返回复查项、相关新反证重开、无效更新/主体/引文/ID拒绝、一次修正与已完成目录精确复用。第一次绿灯时旧h10测试还遇到旧记录没有的下一次模型响应，未虚构新模型输出；最终把该回归明确限定为保存前缀，另用完整预算驱动继续验证。

完整预算的[saved_prefix_loop](saved_prefix_loop/)用4份旧响应注入新提示，搜索返回旧真实结果、本地邻段实际读取。首次反馈现在保留r2，只复查r1，不再因同一空gap重复失败；循环可继续到第二个合法工具动作，在需要第五个未记录模型响应前主动中断。详见[汇总](saved_prefix_summary.json)及[可复现驱动](replay_saved_prefix.py)。这属于反事实控制流回放，提示已变，不能冒称精确同提示缓存、完整h10通过或真实模型改善。

本轮修复新增LLM请求0、token0；没有重新运行旧量化/生成实验。源码基线、红灯、首次绿灯失败均保留。P3.1另外有公开arXiv GET工具验证，其结果与请求单独见[P3报告](../p3_arxiv_tools_20261022/report.md)。
