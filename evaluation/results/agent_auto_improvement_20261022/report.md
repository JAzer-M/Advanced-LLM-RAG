# Agent / Auto 改进与采用边界

2026-10-22。最终Auto改为**RAG优先、明确缺口才升级Agent**；正常路径与固定RAG使用同一提示和证据，不再先付费规划/门控。排版引文、已知复杂主体绑定、模型输入中的审计引文干扰已做针对性修复，回答限制到必要事实。最终251项离线测试通过。

这轮改善了普通路径成本和已知题交付，**未证明Agent/Auto总体质量优于RAG**。h10的最新真实升级仍未完整成功，已可见降级并记录P1。此前8题分数与原始失败保持不变，不把本轮选出的成功案例合并成新准确率。

## 为什么这样设计

固定RAG已经有分解、混合检索、重排和两轮规则补查；8题对照的6道可答题初检都已有关键证据。旧Auto每题还要先规划/检查，普通题也付成本，复杂结构还会被校验阻塞。

最终流程是：初检 → 原RAG生成/引用修复 → 没有明确缺口则直答；有证据不足、无法回答/比较或引用失败信号，则将原问题、原文及目录交给现有Agent。草稿不会进入Agent的事实白名单。Agent仍选择工具、检查新增原文、生成和复核。

一般完整请求原RAG为2调用（分解+回答），旧Auto为4，最终Auto直答为2；引用修复再加1。真实复用初检的a03/a04各只有1次新生成，Agent调用0。**这是调用路径减少，不是重新测出的8题token降幅。**

固定Agent上限仍11；Auto为前置RAG草稿/引用修复保留2次独立probe预算，升级后仍可6次决策/4次回答，总上限13。普通题便宜，复杂题最坏预算增加，均预写账本。工具仍最多3次，32段/24000字符，修正额度仍1次，网络/截断不重试。

升级失败时，只有原草稿引用结构合格才保留它并标注“补查未完成、仅依据初检”，状态degraded，CLI返回非零；loop失败原样保存。引用仍不合格则保持failed。降级不算完整通过，也不保证原RAG内容正确。

完整区别、适用场景与局限见[设计与选型](design.md)。

## 修复了什么

1. `has_source_quote()`仅兼容字母间连字符后的排版空格，原文不修改；改词、句序、拼接和数值符号仍受检查。规划、答案原句的引用不因这项兼容而放宽。
2. 绑定支持明确重复介词场景、两边都有独立关系的比较、唯一场景中的“这些本方法实验”回指；本地重新计算need，保留各自条件，跨方法/数据集错误仍拒绝。它仍是保守规则，不是通用解析器。
3. 检查器输入只含id/subject/need和安全公共场景；生成/复核同样只看绑定需求。混合A/B的原始question_quote留在本地审计文件，避免重复输入重新诱发条件串用。
4. 生成/复核提示限制未问的公式、额外实验说明及冗余引用；不能把公式子项当完整公式。a02真实回归不再出现此前那条附加公式说明。
5. 删除未采用的一次联合门控实验代码；当前Agent仍先独立规划，再看证据判断。已完成需求的反馈稳定性仍待改进，不能通过自动把partial改成supported绕过。

h10最新失败：初始检查将已支持的Self-RAG一侧标partial却给空gap，唯一修正后改为supported；搜索后又做出相同无效降级，修正额度已用完。没有为了交付把它自动升级为supported或重置预算。缓存草稿本身也把RAG问题套到PopQA/TriviaQA，降级标签不把这一条件错误变成正确。

因此本轮只能证明：普通路径不再必付Agent成本；局部误阻塞与无依据附加解释有所改善；升级、真实工具和可见降级可以运行。**本轮没有新的“补齐缺口后完整答对”的h10成功证明。** 历史h10成功属于旧版本开发记录，不能替代本轮失败。

## 建议与剩余工作

当前依然以固定RAG为质量和成本基线。Auto是普通路径低开销的升级入口；固定Agent只在明确需要多步补证据的任务上考虑。若复杂题占多数，直接Agent还可能省掉Auto的前置草稿。没有足够收益时完全可以选择固定RAG。

下一项P1是反馈状态管理：避免没有新相关证据时已完成需求反复被误判，以及无效格式反复消耗共享修正预算。可以研究只复查受新证据影响的需求，同时保留真正冲突的重新打开能力；本轮未实现，不加更多工具/框架或继续针对h10付费调试。未来另建独立题集，再评估隐性漏答、过处理、补证成功率与成本。P3未开始。
