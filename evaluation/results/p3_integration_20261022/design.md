# P3.2：本地缺源后的有预算arXiv闭环

用户授权完成P3.1之后的下一步，并要求说明流程与原因。实现采用独立的`src/arxiv_evidence.py`和main的小接缝，不扩写原本地Agent的动作协议或改造索引。

1. 默认保留原三模式；Agent/Auto显式`--allow-network`才允许外部GET。初检证据已齐时沿用原路径，无联网决策成本。
2. 只有本地Agent正常`model_stop`且仍有缺口时进入候选检查。元数据别名能明确识别库内论文的需求继续视为本地检索缺口，不联网补替代论文；其余交给一次路由决策，允许选择local_only停止。
3. 路由只看绑定需求/缺口和本地目录，选择一个未满足需求并给出完整原论文标题；Python构造一次`ti:"完整标题"`查询。不能识别标题则保守停止，标题本身仅是待核验的书目线索。只搜索一次、最多3篇；摘要/题录仅用于定位，不进入事实白名单。
4. 再用一次决策从真实返回的版本ID中选择一篇，可拒绝选择。不能自行编造ID、网址或改版；明确匹配所问主体及原论文身份由元数据与后续原文共同核对。
5. 下载固定版本PDF，复核文件哈希、版本及原文身份。按原文连续位置切出候选，BM25预选最多120、复用已加载BGE取最多6段，同时保留全部PDF和原始提取文本。追加时总量仍32段/24000字符，原本地证据不丢弃。
6. 外部证据保留独立evidence_id、版本、网址、页码、PDF哈希和原文位置。为兼容现有整数引用校验，仅本次运行分配高于本地最大ID的编号，明确origin=arxiv，不写入知识库或冒充本地版本。
7. 第三次联网决策复用原assess_evidence检查合并原文；仍有缺口按预算停止。复用原answer_with_review初稿/复核/最多一次修订，返回引用表及程序生成的外部来源链接。

本地决策仍6、工具仍3，回答阶段仍4；启用联网另增最多3次network决策和2次公网工具调用（搜索+读取一篇），完整Agent最大14次模型请求、Auto最大16。公网GET和模型请求分别计数；HTTP/解析/模型失败均保留，不隐式重试，不改写初检草稿为事实证据。

验收：实际main入口的本地直答/联网/失败/不联网条件；错误ID、错误论文、伪原文、证据与调用预算、引用闭环和旧272项回归；之后先冻结两道工程冒烟题与调用上限，再最小真实运行并人工核对原文。不是P3完整新留出对照，不重算历史分数，不提交或推送。

首次真实查询仅用短方法名和比较词，搜索返回后续论文而安全拒答；一次提示补充仍产生任务词并遇到不支持的旧式ID。两次原始结果均保留。最终将自由检索式改为书目标题字段，由Python固定标题查询，工具和调用预算不增加；真实复验单列为同题开发回归，不回改初次结果。
