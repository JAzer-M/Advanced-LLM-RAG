# QASPER 独立评测协议（运行前冻结）

日期：2026-10-24（Asia/Shanghai）。本文件在任何评测运行之前写定；运行后不修改抽样、评分规则或判分提示。若之后发现问题，另起新一轮并在报告中说明，旧结果保留。

## 目的

用第三方人工构造的科研论文问答数据，对 PaperLens 的三种模式（固定 RAG、Agent、Auto）做同条件对照，补上"题目由项目方自己出、样本只有 8～12 题"的短板。

## 数据与抽样

- 数据：QASPER v0.3 测试集（Dasigi et al., NAACL 2021，CC BY 4.0），官方压缩包 `qasper-test-and-evaluator-v0.3.tgz`，压缩包 SHA-256 记录在 `frozen_sample.json`。
- 候选：测试集中 ID 为 arXiv 格式的论文。
- 抽样：候选论文按 ID 排序后用固定种子 `20261024` 打乱，按顺序整篇纳入（该论文的全部有效问题），直到累计问题数 ≥ 50。arXiv PDF 下载失败的论文整篇跳过，继续取下一篇。实际抽到的论文与问题写入 `frozen_sample.json`。
- 论文来源：从 arXiv 下载当前版本 PDF（可能与 QASPER 使用的全文版本不同，属于已知偏差），保存在本机 `data/raw/qasper-test50-20261024/`，不随仓库发布。

## 系统配置

- 知识库：用项目自己的建库脚本 `build_semantic_index.py` 从这些 PDF 新建独立版本 `qasper-test50-20261024`，所有 PDF 按双栏读取（QASPER 论文多为 ACL 双栏排版）；不切换当前激活库，也不影响网页库。
- 模型：运行时 `api.local.json` 中的模型服务（预计 `cn:glm-5.3`），实际设置写入 `run_settings.json`。
- 三种模式使用同一知识库、同一模型、同一批题；联网补证据关闭；代码与默认预算不为本评测调整。
- 失败不自动重试，失败计入分母。
- 评测脚本只缓存检索模型对象，避免每题重复加载，不改变检索、预算或回答逻辑。

## 评分

1. **Answer F1（官方口径）**：答案与每位标注者参考答案的词级 F1（小写、去标点和冠词），取最大值，再对所有题平均。参考答案按官方规则构造：不可回答 → `Unanswerable`，抽取式 → 片段用逗号连接，是非题 → `Yes`/`No`，否则用自由文本。
   - 系统回答去掉引用编号和 Markdown 标记后计分。
   - 回答不超过 80 个词、且第一句表示论文未提供该信息时，记为 `Unanswerable`（规则见脚本 `DECLINE`）。
   - 已知局限：系统回答通常是完整句子，而参考答案多为短语，词级 F1 会系统性偏低；这与 QASPER 论文中的生成式基线面临的问题相同。
2. **Evidence F1**：官方定义为预测证据段落与标注证据段落的段落级 F1（只计正文段落）。系统的分块与 QASPER 段落边界不同，因此先做对齐：某段落至少一半的 5 词片段出现在回答实际引用的分块中（或反之），即视为预测了该段落。这是**近似对齐**，报告中如实说明。
3. **检索命中率**：选入上下文的分块中，是否至少对齐到一个标注证据段落（只统计有标注证据的题）。
4. **拒答**：多数标注者认为不可回答的题中系统拒答的数量；可回答题中系统误拒答的数量。
5. **大模型判分**：用同一模型服务，按脚本中固定的提示词对每个回答给出 correct / partially_correct / incorrect。判分模型与作答模型相同，可能偏向自己的表述，所以只作为 F1 之外的补充。
6. **成本**：每次运行的模型请求数、总 token、耗时。

官方评测脚本 `qasper_evaluator.py`（压缩包自带）用于交叉核对 Answer F1；若其接口与预期不同，只记录其输出，主结果以本协议的实现为准。

## 结论边界

- 约 50 题、约 17 篇论文，属于小样本；不报告显著性。
- 判分与作答为同一模型服务。
- 论文 PDF 版本可能与数据集全文不一致；Evidence F1 依赖近似对齐。
- 结果只代表本次固定配置（模型、知识库、默认预算），不外推到其他模型或领域。
