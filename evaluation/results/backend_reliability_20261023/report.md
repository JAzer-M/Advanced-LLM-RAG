# 后端稳定性修复：改动、效果与边界

2026-10-23（Asia/Shanghai）。已核对当前文件清单、进度、相关生产代码与上一段对话全部11个用户回合，按照最后提出的后端交付问题完成修复。**314项离线测试通过；一次真实n06/Agent遇arXiv搜索超时后，返回明确的未核实说明、原文和停止原因，不再只有空答案。外部来源可用性尚未恢复。**

本轮沿用普通函数、字典、列表和既有模块，没有新增框架、依赖或生产CLI。依据Matt Pocock诊断流程先复现再修复，使用Karpathy精准改动原则；鼠鼠实习工具与本次后端故障修复无直接关系，未调用。历史题集、分数、失败、知识库和私有配置保持，没有提交或推送。

## 1. 为什么修这些问题

上一轮两次搜索HTTP429后，n04/Auto只保留初检缺口，n06/Agent直接failed、无最终答案。HTTP记录缺少Retry-After和错误响应信息；成功、部分完成和运行时异常的返回字段不统一，调用者还依赖旧的抛异常方式。这些会直接影响使用和界面交付，比可选背景是否齐全更值得先修。

本轮没有尝试证明429已经解决，也不循环请求刷成功。选择“保留诊断、明确停止、交付已有内容”，使外部故障不会造成无解释的中断，再将后续是否重试或使用经过验证的缓存留给实际需求。

## 2. 修改及实际效果

| 修改 | 现在的行为 | 原因 |
| --- | --- | --- |
| 外部失败后的有限交付 | 429/超时/传输失败后，Auto可保留合格初稿；Agent或没有合格初稿的Auto仍使用已校验本地输入。全missing直接说明缺口，部分支持仍走原回答/复核 | 已有证据可以继续发挥作用，暂时取不到资料也应有清楚说明 |
| 获取失败与未报告分开 | 顶层`source_unavailable`；回答输入中的missing/partial缺口改为中性“尚未核实”，原判断仍保存在loop | 防止复制模型先前未经原文证明的“论文未报告”断言 |
| HTTP诊断 | 保存失败阶段、状态、必要公开响应头、最多2048字节错误正文、耗时；解析Retry-After秒数/HTTP日期，非法/缺失为null | 可以区分限流、超时、其他HTTP错误和校验失败；错误正文不进事实证据 |
| 三模式统一返回 | `status/answer/answer_status/stop_reason/ledger/selected_ids/actions/api_summary/network`；运行时故障有明确结果，入口参数错误仍抛出 | 调用者可以直接显示状态、答案或原因、证据、行动与成本 |
| RAG成本及失败保留 | 默认路径分解、生成、引用修复共用调用审计；生成失败仍保留初检原文 | 避免失败时丢证据，成本按实际调用尝试记录 |
| 采集器适配 | `evaluation.run_answer_evaluation`不会把返回的failed/degraded重标completed | 返回故障结果代替抛异常后，评测必须保留真实失败 |
| 回答与复核优先级 | 明确子问题、事实、关键条件和引用优先；定义/步骤按任务需要，可选背景、表达与组织不阻断交付 | 减少对非必要细节的苛求，同时保留正确性约束 |

生产改动为`main.py`、`agent.py`、`src/arxiv_tools.py`、`src/arxiv_evidence.py`、`src/agent_answer.py`、`src/api_llm.py`、`evaluation/run_answer_evaluation.py`。API生成辅助函数仅增加可选审计回调，原调用方式仍可用。原检索、知识库配对、来源/哈希/连续引文校验及调用预算保持。

详细字段、状态和调用顺序见[后端返回约定](../../../docs/BACKEND_RESULT.md)。`completed`只表示处理完成；`degraded`和`failed`的CLI退出码仍为1，不能把有解释的故障计作完整事实任务成功。

## 3. 回答的三层优先级

1. **必须满足**：回答用户明确提出的子问题；保留会改变结论的单位、条件和范围；不编造、不串主体、不误引。正常输入应得到答案或明确说明。
2. **按任务需要**：为复现实验补定义、步骤、参数；为判断取舍补必要限制条件。
3. **可以省略**：不影响当前任务的背景、延伸、可选例外；不因措辞或组织方式不同而判失败。

改动落在RAG回答提示、Agent回答提示和复核提示；没有放松原文连续引文、真实引用编号、论文身份和预算校验。本轮验证提示与程序行为，不宣称已经量化了自然语言复核误拒绝率的改善，也没有重算旧严格评分。
