# Rewrite / HyDE 与本地 2B 同题对照

日期：2026-10-18。承接本轮用户要求：随机提出三个 questions.json 之外的问题，观察查询增强效果，并以原本地模型为参照评价换模型的改善，不比较商业模型排名。

## 结论

这三个新问题中，现有 rewrite 融合路径与 rewrite+HyDE 没有改变任何一题的最终 Top-10；只开 HyDE 仅替换池化题第十条，没有增加关键证据。不能把答案措辞的变化解释成检索增强收益，默认开关继续关闭。

真正清楚的改善来自最终回答：在完全相同提示、证据、双方最大 512 输出 token 下，原 Qwen3.5-2B 的预设要点评分为 8.5/12，DeepSeek 为 11.5/12，多覆盖 3 分；本地出现的移位/掩码作用混淆、池化分类错误及无依据因果，在 DeepSeek 的这三次回答中未出现。这是三题开发性人工评分，不是总体准确率提升，也不是统计显著结论。

上一轮没有运行 run_evaluation.py；这次已经实际完成。原有五题 Top-5 评估中，改写查询单独检索有收益，但主流程实际使用的“原查询+改写融合”没有收益。该脚本没有 HyDE 分支，HyDE 由本次三个新问题的 Top-10 实际流程另行观察。

## 1. 实验设计与控制

采用种子 20261018，从每篇论文事先列出的三个候选问题中各抽一题。问题、候选池、抽样方式和 12 个评分点在首次答案产生之前写入 [protocol.json](../evaluation/results/rewrite_hyde_20261018/protocol.json)。没有修改 questions.json、Gold、原始论文或现有索引。

三个问题分别为：

1. In the Transformer decoder, how do the shifted target embeddings and masked self-attention prevent access to future target tokens during training?
2. How do overlapping pooling windows differ from non-overlapping pooling in the DCNN paper, and what effects did the authors report?
3. How does the VGG paper distinguish scale jittering during training from multi-scale evaluation at test time?

每题运行四种条件：base、rewrite、hyde、both。使用真实 main 流程：分解、Dense/BM25、RRF、重排、证据与生成。辅助分解/改写/HyDE 每个精确提示只生成一次，后续组合复用，最终回答每组实际生成，避免比较中混入不同辅助查询的随机变化。原始分解、改写、假设文档和调用均留档。

rewrite 在当前 main 中实际是 USE_MULTI_QUERY：保留原查询，再把改写查询的 Dense/BM25 加入 RRF；不是替换原查询。HyDE 只用于检索，其假设文字没有直接作为论文证据注入最终回答。

Embedding、BM25/FAISS 和 BGE 参数均保持主流程设置：候选 60、最终 Top-10，分解开着。CPU 模型在一次实验进程中复用，避免重复加载；因此记录的耗时不能直接当作四种配置的公平延迟基准。没有改写生产文件的默认开关。

另外，从清理快照直接执行原本地生成源码，不恢复到主流程：Qwen/Qwen3.5-2B、bfloat16、GPU、do_sample=False、max_new_tokens=512。分别重放 base/both 的三个最终提示，共六次本地生成；输入与相应 API 结果逐字相同。比较的是最终生成能力，未用本地模型重做分解、rewrite 或 HyDE。

为控制输出预算，又对 both 三题补跑 DeepSeek max_tokens=512，与原本地上限相同；保持关闭思考、temperature=0。不同模型 tokenizer 不同，512 上限是预算控制，不等于等算力或等成本。前两题本地只生成 254/339 token，没有触及上限，因此其中的概念错误不能用截断解释。

## 2. 三题技术核对

### n1：目标移位与因果掩码

知识与论文核对：预测目标 y_i 时，解码器该位置的输入对应先前 token；移位避免直接把当前标签放在同一预测位置。训练时后续输入位置仍可能含有当前或未来目标，仅移位无法限制注意力访问，必须再用因果掩码。屏蔽未来位置时，将非法连接的 softmax 前分数设为负无穷，其注意力概率为零。论文 chunk 25（p3）明确说两者结合，chunk 40（p5）给出负无穷掩码实现。

本地答案的问题是，在“Shifted Target Embeddings”段落单独断言：`Consequently, the model is unable to attend to future positions`。这把只有联合机制才能保证的性质归给了移位本身；最后再说二者合作不能消除前面的错误因果。它还说相对于 input sequence 移位，未明确是与目标标签的对齐关系，且整篇没有 [N] 引用。

DeepSeek 512-token 对照明确说 masking combined with offset embeddings，正确限制输出依赖为位置 i 以前的已知输出，并给出 [1]/[8] 原文支撑。没有把输入位置可见到自身与输出标签可见到当前 y_i 混为一谈。

冻结的分解结果也值得留意：它把“联合防泄漏”拆成两个“分别如何防泄漏”的子问题，可能引入错误前提。四组和两个模型都使用相同最终原问题/证据，本轮没有为了评分人为修改这一点；这是未来分解质量应关注的边界。

### n2：重叠池化

正确关系：窗口宽度 z、步长 s；s=z 时相邻窗口不重叠，s<z 时重叠。论文使用 s=2,z=3，对照是 s=2,z=2，输出维度相同；报告 top-1/top-5 错误率分别降低 0.4/0.3 个百分点，并观察到较难过拟合。支撑为 chunk 147/148（p3）、153（p4）。

本地答案开头把 `s=2,z=3` 叫作 `standard non-overlapping scheme`，是实质性分类错误；后面又正确写 s=z，形成内部矛盾。它还补出“更多邻域上下文导致误差降低”的因果，但当前段落只定义窗口并报告实验，没有证明这条解释；引用同主题段落并不等于得到因果支撑。

DeepSeek 正确区分两种窗口配置、比较条件和误差变化，并把过拟合描述为作者观察。其 0.4%/0.3% 沿用原文用法；更严谨的中文说明是错误率下降相应百分点，而非相对降低同样百分比。

### n3：训练尺度抖动与测试多尺度

训练时对每张图随机选择 S∈[256,512]，缩放后再取固定 224×224 训练裁剪，作用是增强训练分布。测试时用已训练模型运行同一图的多个 Q，并平均类别后验，不是为每个 Q 重新训练。固定 S 的模型用 Q={S−32,S,S+32}；尺度抖动训练的模型用 Q={256,384,512}。训练抖动即使只用单测试尺度也有收益；多尺度测试是在推理阶段再聚合多个尺度。

DeepSeek 区分了随机训练采样和测试后验平均，也保留了两类模型的不同 Q 条件。本地基本流程大部分正确，但用固定 S=256/384 的训练步骤代替明确的随机范围，把“深层小卷积核优于浅层大卷积核”的结果当成 scale jitter 的 Exception，产生了无依据的逻辑关系和无关内容。两次本地生成都达到 512 上限；原实现没有保留最后 token ID，所以只认定触及预算上限，不冒充已经确认 EOS 状态。

共同缺口是固定 224 裁剪：四组都没有取到 chunk 259/260，输入证据里缺少这项信息。本报告可通过整篇论文核对说明它，但封闭证据回答不能凭常识补写。两个模型均按预设复合评分点记部分分；这是检索覆盖边界，不全部归咎于生成模型。

## 3. 相对本地改善多少

事先约定每题四个核心点，每项 1=完整正确、0.5=部分、0=遗漏/错误；无依据因果、逻辑关系和引用另外记录。由同一助手人工核对，不是独立盲评。完整评分和原文定位见 [manual_review.json](../evaluation/results/rewrite_hyde_20261018/manual_review.json)。

| 同提示、同证据，双方 512 上限 | 本地 Qwen3.5-2B | DeepSeek v4.1 Flash |
| --- | ---: | ---: |
| n1 移位与掩码，满分 4 | 3.0 | 4.0 |
| n2 池化，满分 4 | 2.0 | 4.0 |
| n3 尺度，满分 4 | 3.5 | 3.5 |
| 核心点合计，满分 12 | 8.5 | 11.5 |
| 有有效编号引用的回答数 | 2/3 | 3/3 |
| 达到输出预算上限 | 1/3 | 0/3 |

DeepSeek 三题实际输出 144、128、401 token，均 finish_reason=stop；本地为 254、339、512。提升不只体现在篇幅：移位的因果关系、重叠窗口分类这两个技术错误消失，且引用位置更直接。n3 两者的核心点同分，不能说每题都有同样增幅；局部评分也不能覆盖所有无关/错误附加关系，必须结合原文审阅。

这份结果不应写成“总体准确率提高 25%”。可信的描述是：这三个新问题、当前证据和原本地生成设置下，多拿到 3 个评分点，并减少了明确概念错误与无依据扩展。没有比较其他商用模型，也没有做大规模测试或稳定性统计。

原始对照在 local/ 与 matched_512/；每份 JSON 保存完整相同提示、context、引用来源和生成元数据，MD 保存便于阅读的原始答案。

## 4. 开启 rewrite / HyDE 的效果

| 条件 | 与 base 的 Top-10 完全相同 | 观察 |
| --- | --- | --- |
| base | 3/3 | 原查询和问题分解已检索到大部分核心证据 |
| rewrite | 3/3 | 融合后未增加最终核心证据 |
| HyDE | 2/3 | 只把 n2 第十条从 chunk 102 换为 164；定义/实验关键证据不变 |
| rewrite + HyDE | 3/3 | 三题最终 prompt/context 都与 base 一致 |

四组人工要点评分为 11.0、11.5、11.5、11.5/12，但小差别来自 n3 是否明确保留“训练抖动即使单尺度测试也有收益”的条件。该题四组最终提示逐字相同，因此不能把多出的半分归功于 rewrite/HyDE。此前已经观察过 temperature=0 时代理输出仍不同，本轮同样不能把随机措辞差异当算法收益。

四组均未补到 n3 的 224 裁剪证据。扩大候选并不必然改变最终重排；新生成的查询也可能只复述原查询已有概念。当前没有开启它们的收益证据，默认继续关闭。这个结论限于当前三个新题及已有五题指标，不是宣布方法普遍无效。

每题的原始 rewrite、HyDE 与分解可在 both 的 api_calls 中查看；辅助响应复用有明确标记，不算作实际新请求。

## 6. 本次发现并修复的问题

VGG 原答案带数学区间 `[256; 512]`，旧 check_citations 将它误判为 malformed citation，触发了不必要的引用修复。真实新题可重现，最小检查也失败：

```python
check_citations('Training scale S is in [256; 512] [1].', registry)
# 旧结果：malformed_markers=['256; 512'], structure_passed=False
```

最初考虑编号越界、区间误判和服务问题，检查发现编号 [1] 合法，误判来自正文方括号。对 src/citation_validation.py 做了一个局部修正：排除分号分隔的数值区间，保留 [N]、越界编号、[1,2]、[E1] 的原有处理。没有泛化忽略所有方括号，也没有针对 VGG 写特殊答案规则。

修正后最小示例与小数区间通过；越界、组合引用、记录编号、只有区间但无引用仍不通过。12 份真实原始草稿用新检查器回放，均不再触发修复，零额外 API 调用；此前六题的引用结构也仍通过。见 citation_interval_fix.json、citation_fix_replay.json。

四组主流程和本地重放的原始记录产生于修正前，保留当时的代码哈希和误判状态，不覆写成新成功记录；人工评价使用修正后的编号检查。等预算三题产生于修正后，提示和证据仍与本地逐字相同。这处修改不影响检索、问题或生成提示。

## 7. 请求、失败与代码环境

本轮共 41 次实际 API 请求：39 成功、2 次 HTTP 503。第一次发生于旧 Gold 评估的首个分解请求，保留失败后重跑该评估完成；第二次发生于 n3 rewrite 的误触发引用修复，原始已生成草稿也保留，只补跑失败组合。17 次辅助响应复用不计实际请求。39 次成功均 finish_reason=stop。

真实请求分布：分解 3、回答 13、HyDE 3、rewrite 3、引用修复 5、旧 Gold 评估辅助请求 11、等预算回答 3。本次的五次引用修复都发生在区间误判背景下；修正避免了这类额外调用，而不是增加模型重试。完整审计见 request_audit.json，失败文件在 failures/。

原本地模型六次生成均完成，使用现存缓存和 GPU，无下载或安装；环境缺少优化 kernel 时沿用原实现的 PyTorch 参考路径，没有为实验升级依赖。因此不据本轮耗时宣称模型延迟倍数。

生产源码只修改 citation_validation.py。main、llm、其他 src、questions.json、配置与全部数据哈希与实验开始一致；默认 rewrite/HyDE 仍关闭。26 个 Python 文件语法通过，未增加长期测试脚本；新产物未含实际 Key。

实验驱动保存在项目外的 Codex 产物目录，路径和校验和写入 protocol.json；本地原生成源码从上轮清理快照读取，没有把旧代码或测试重新放回项目。复现实验可以运行该驱动的 ablation、local、matched、metrics 模式；它跳过完成记录，保留失败尝试，默认不会覆盖成功结果。

源码没有提交或推送。当前结论支持继续使用较强生成模型改善回答，同时保留默认查询配置；进一步检索改进应围绕真实漏检，例如本次缺失的训练裁剪证据，而不是先把所有开关打开。
