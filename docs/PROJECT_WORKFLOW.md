# RAG 项目全流程

目标：做一个能查论文原文、给出引用、发现证据缺口并按需补查的科研问答系统，再用实验说明它的效果与成本。

整体路线：基础 RAG → 检索与回答改进 → P0 论文与知识库管理 → P1 评测基线 → P2 本地 Agent → P3 按需联网 → P4 展示与交付。

## 一、搭建基础 RAG

1. 选少量论文，明确希望系统回答哪类问题。
2. 解析 PDF，保留正文、论文来源、页码、标题和章节。
3. 将正文切成可检索片段，为每个片段生成向量。
4. 保存 FAISS 索引及配对的分块原文。
5. 输入问题，检索相关片段，交给模型生成带引用的回答。

## 二、改进检索与回答

1. 比较分块方法，检查重要定义、条件和数值有没有被切散或遗漏。
2. 组合 Dense 与 BM25，用 RRF 融合，再用 BGE 重排。
3. 对多需求问题进行分解，保留各子问题的关键证据。
4. 对比改写、HyDE、候选数和最终证据条数，按实验决定是否采用。
5. 整理原文证据、主体和引用；分别定位“没找到”“没选入”“有证据却没讲全”等问题。

## 三、P0：扩充论文与管理知识库

1. 围绕项目主题选择论文，固定下载版本并校验文件。
2. 解析、分块和编码，建立独立知识库版本。
3. 核对索引、分块、来源和数量，保存可追溯信息。
4. 保留旧版本，支持显式选择、切换和回退。

## 四、P1：建立可复核的评测基线

1. 准备单篇、跨篇和不可答问题，冻结 Gold 原文与评分要求。
2. 运行固定 RAG，保存检索排名、入选证据、回答和调用记录。
3. 检查 Precision、归一化 Precision、Recall、MAP 和 MRR。
4. 人工核对核心点完整性、主体与条件、引用支持及拒答是否合理。
5. 记录 token、调用量、耗时与失败，形成后续 Agent 的对照基线。

## 五、P2：实现本地最小 Agent

| 小步骤 | 具体要做什么 |
| --- | --- |
| P2.1 需求与证据判断 | 从问题抽取需求；逐项判断证据是充分、部分、缺失还是冲突；提出行动建议。 |
| P2.2 本地工具 | 实现搜索知识库、读取邻段；返回真实原文和出处；检查参数、边界与调用记录。 |
| P2.3 执行与反馈 | 执行所选工具，更新证据并重新判断；控制动作、调用和上下文预算；无进展或预算耗尽时停止。 |
| P2.4 回答与复核 | 综合已有证据生成答案，检查漏答、主体、数值、条件和引用，必要时有限修订。 |
| P2.5 对照验收 | 用同题、同库、同模型比较固定 RAG 和 Agent；观察质量收益及额外成本，再用新留出题验收。 |

Agent 的运行链：用户问题 → 需求清单 → 搜索证据 → 检查缺口 → 选择并执行工具 → 根据结果再判断 → 回答或说明证据不足。

## 六、P3：按需接入联网证据

1. 判断缺口来自本地检索不足，还是知识库确实缺少资料。
2. 需要外部资料时，搜索可信来源并读取可访问的正文。
3. 保留网址、论文版本、原文及获取记录，核对外部证据是否支持需求。
4. 将外部证据用于回答；需要长期复用时，再纳入知识库版本管理。
5. 检查联网带来的质量收益、失败情况和额外成本。

## 七、P4：展示、复现与项目交付

1. 做一个简洁界面，展示问题、证据、行动记录、答案和停止原因。
2. 流程复杂到需要时，再引入编排工具；保持已验证的行为和边界。
3. 整理环境、配置示例、启动方式、评测入口和代表性案例。
4. 汇总实验对照、失败案例与改进依据。
5. 准备项目讲解、简历与面试材料，所有效果描述都对应真实记录。
