## VGG 失败案例：候选、上下文和生成

手工问题：`What makes the small conv kernels in VGG useful?`。四路 RRF 中，核心 Chunk 246 只出现在 Original BM25 Rank 5；融合后为 Rank 22，被 Top-20 截断。扩到 Top-40 后进入候选，BGE 最终 Top-5 仍未选择它。临时过滤 VGG 时升到重排 Rank 3；这是诊断，不能写死到通用问答。

核心证据：

| ID | 页 | 内容 |
| --- | ---: | --- |
| 246 | 2 | 两层 3×3 对应 5×5，句子断在 three |
| 250 | 3 | 三层对应 7×7，更多非线性 |
| 251 | 3 | 27C² 对 49C²，原 PDF 抽取有公式异常 |

章节扩展曾从 Top-5 扩至 14 条：230,380,246,310,305,245,247,248,249,250,251,252,253,254。答案更完整，但引入表格与邻近主题噪声。首次 Gold-only 因重复赋值产生重复上下文，无效；正确 `[246,250,251]` 实验中，Qwen 仍把三层 3×3 的感受野错说为 5×5，并把引用集中在末尾。

结论：检索覆盖、上下文完整性、模型事实理解和引用遵循需分别检查。不要无限扩大上下文或用手工 Gold ID 美化结果。恢复后的通用问答曾正确回答 Transformer 位置编码，并引用 Top-5 中第 5 条证据。

## PDF 与分块限制

VGG p2 的 Discussion 正文在 `three` 处跨页；p3 的 Table 1/2 在续接正文前。p3 的 `find_tables()` 返回 0，文本块只能初筛标题候选，不能认为整张表已识别。公式提取含空字符与 `32C2` 等异常，未修复。

V2 原型只输出 Block ID、页码、BBox、文本及 `table_candidate/figure_candidate`。历史验证 Table 1/2 的标题块可识别，不包括整表范围、跨页合并、公式保真或 V2 索引。当前决定暂缓深度解析。

Semantic 逐 Document 切句，无法跨页接句；会过滤 ≤10 字符句子及 <50 字符 Chunk，超长句按字符回退。该损失在本轮整理中保留，后续应独立评估。
