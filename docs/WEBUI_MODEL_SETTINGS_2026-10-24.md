# WebUI 阅读布局与模型配置交接

## 已完成

- 按用户提供的两张建议截图调整首页与阅读页：输入居中、提交后收起为可展开的问题栏、阅读区约7:5分栏、同一纸面与细线、正文16px、辅助文字提高可读性。
- 引用按首次出现顺序在展示层编号，答案与右栏统一朱橙chip；悬停显示原编号，原始结果不改。复制使用原始答案并附原编号来源，避免脱离页面后编号无法追溯。
- 状态、耗时、模型请求与token移到答案上方。展示实际路径和可取得的本地需求覆盖；明确本地检查不包含后续联网补证据，不把历史字段缺失写成全覆盖。
- 桌面引用定位只滚动右侧原文区，避免整页跳动；390px下上下排列，无横向溢出。模型窗口在390px宽度下为352px，密钥输入为空。
- 模型配置流程：地址与API Key → 获取模型 → 选择模型 → 保存。获取请求为所填地址加 `/models`，使用待保存密钥；不生成回答，不自动保存。
- 服务不支持列表时可展开手动模型ID。模型列表是该端点和凭证实际返回的清单，不保证每个ID都兼容当前文本问答请求，也未实现服务商私有分页协议。
- 保存仍使用原有 `api.local.json`，原子替换，权限0600；旧密钥不回显、不存浏览器。改变地址必须显式提供对应密钥，获取列表不向新地址转发旧密钥，禁止携带鉴权的重定向。已有高级调用参数保留。
- 当前为单用户本机设计，共享一个配置文件；没有实现多用户隔离或公网部署。

## 产品与论文的边界

当前是有可用界面的本地原型。终端启动的是本机后端；要做到只需网址，需要部署常驻后端、存储和索引，并补齐身份/密钥隔离、任务并发等产品能力。也可以只做桌面打包，隐藏启动终端；本轮均未执行。

永久加论文的处理链：PDF或arXiv论文 → 提取正文与页码 → 分段和向量化 → 生成成对的索引与chunks文件 → 校验新版本 → 切换问答使用的版本。现有脚本支持下载与版本化构建，但UI尚无上传/导入入口，Agent和UI仍绑定八篇版本；不能只把PDF放进文件夹就说已入库。

arXiv搜索API提供元数据、摘要和论文链接，全文还需获取和解析。当前补证据按本次任务下载固定版本PDF、解析并保留运行记录，不自动扩充永久库。论文来源在云端与知识库部署在云端是两个概念：可以不保存到用户电脑，但仍需由后端获取、处理全文；若后端仍在本机，这些操作仍由本机承担。

官方参考：https://info.arxiv.org/help/api/basics.html

后续按小步推进：先验收模型配置，再做单篇PDF/arXiv导入与可回退版本，之后决定桌面打包还是网站部署。
