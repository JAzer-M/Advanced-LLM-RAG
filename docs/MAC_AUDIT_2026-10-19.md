## 优先处理的缺口

1. **Mac 启动验收**：稳定批量编码运行，准备 BGE 缓存与 API 配置。先跑一个位置编码问题，再核验跨论文题和库外拒答，结果写新目录，保留历史记录。
2. **生成截断未被拒绝**：`src/api_llm.py` 对非空正文直接返回，未拒绝 `finish_reason=length`。本次使用本地 mock 确认截断正文仍被接受；应向主流程/评估明确返回未完成状态，不能计作正常完成。
3. **纯中文 BM25 的零分噪声**：分词只提取 `[a-z0-9]+`。实测“为什么需要位置编码”得到空词项，BM25 返回 ID 0/1/2，分数全部为 0；这些候选仍可能参与 RRF。先避免无有效匹配的稀疏候选进入融合，再根据中英题集决定查询翻译或分词策略。
4. **知识库不能安全切换版本**：main 固定读取 Semantic 路径，构建器先写 index 再写 chunks；中断可能留下不匹配的一对文件。扩库前支持独立版本目录、成对验证后切换，保留旧库可运行。
5. **稳定标识尚未具备**：chunk_id 是数组位置，检索返回时也使用位置；重建会改变引用身份。P0 应区分持久文档/片段标识与 FAISS 行号，不能仅添加 UUID 而不调整映射。
6. **评测与扩库适配**：run_answer_evaluation 的题目参数写死 q1～q6，检索评价固定 Top-5/候选20，而生产为 Top-10/候选60。保留历史口径，另补生产一致的设置及可扩充题集。

其他已有边界：问题分解可能改变联合机制的前提；全局重排可能漏掉子问题证据；PDF 公式、表格、跨页句子仍不完善；主体归属与引用检查是有限规则；每次 main 调用重新加载模型。这些应以新增失败案例驱动修改，避免同时大改所有环节。

### 改动

- `src/api_llm.py`：共享纯文本生成只接受 `finish_reason=stop` 且正文非空。对 length、content_filter、tool_calls 或缺少结束状态的响应，抛出 IncompleteResponseError（RuntimeError 子类），携带部分正文、模型标识、用量和请求参数；用于分解/查询增强的共享入口和最终回答入口均会收到该错误。原有正常返回格式不变，不自动重试或增大 token 上限。
- `evaluation/run_answer_evaluation.py`：错误留档额外保存未完成响应，现有收集器将该题记为 failed、以非零状态退出，并清除旧成功 MD；保留部分正文供核查，不发布为成功答案。
- `src/bm25_retriever.py`：空词项直接返回空列表；评分后排除零分候选，再排序取 Top-K。保留可能合法的负分匹配，而非直接使用 score > 0 过滤。分词策略未变，纯中文语义匹配仍由 Dense 承担。
