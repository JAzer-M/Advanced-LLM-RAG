# 网页PDF入库：实现与验收

## 本轮交付

网页“论文库”可以选择1～5篇PDF（合计20MB以内），点击“添加并入库”，后台自动解析正文/页码、分段、编码、发布配对索引并切换网页知识库。每篇最多200页；可显式选择双栏阅读。暂不支持OCR、删除论文或网页回退按钮。重复内容通过SHA256跳过；同名不同内容使用哈希后缀区分。

批次内任一新文件解析/构建失败，本批新论文都不加入当前库。后台实际阶段逐项显示，不伪造百分比。刷新后可从浏览器保存的任务ID继续查看，任务状态落盘；重启后进程已经退出但未完成的任务显示中断。

## 后端修改清单

| 文件 | 修改与目的 |
|---|---|
| `webui/library.py`（新增） | 管理网页独立版本指针、PDF接收与内容哈希、标题提取、异步构建核心逻辑、原子提交和状态文件。复用原PDF解析/语义分段/MiniLM编码及知识库发布校验。 |
| `webui/server.py` | 增加`POST /api/imports`和`GET /api/imports/{id}`；启动独立导入进程。元数据从网页当前库读取；问答worker在提交时取得明确版本，三种模式使用同一份配对库。 |
| `main.py` | Agent/Auto允许显式传入合法知识库版本，并将其写入运行协议及传给检索。未指定版本仍使用原八篇实验默认值。 |
| `agent.py` | 工具执行的限制从“只能八篇版”改为“所有问题和工具资源必须属于同一版本”；保留输入原文核验。 |
| `src/agent_tools.py` | `load_search_resources(version=原八篇版本)`支持指定新库；原调用默认行为保持。 |
| `.gitignore` | 排除`data/webui/`，避免用户上传PDF、导入日志及私有指针进入Git；新增索引版本继续由既有规则忽略。 |

前端`webui/app.js`、`style.css`增加上传表单、双栏选项、任务状态与更新论文列表；不引入框架或新依赖。

## 文件与提交边界

- 原八篇：`all-papers-8-20261020`，1397段。
- 网页当前：`webui-72bf8b69e9cf45f28135637e5ead075c`，9篇、1767段，增加Mamba固定版本`2312.00752v2.pdf`的370段。
- 网页指针：`data/webui/library.json`；与实验用`data/processed/active_kb.json`分离，后者没有切换。
- 配对索引：`data/processed/versions/<version>/`；原论文片段和原向量逐项比较一致，旧版本没有覆盖。
- 上传及状态：`data/webui/imports/<id>/`。原PDF保留以便检查；重复上传当前仍保留该次原文件，未做自动磁盘清理。
- 新版本构建完成并校验后才原子替换网页指针。构建失败不会破坏旧库。运行中的问答固定其提交版本。

## arXiv导入是什么意思

未来入口允许用户粘贴特定论文链接或编号，例如`2312.00752v2`。后端下载这份PDF，再进入本轮已经完成的同一条入库流程。用户不用手动先下载再上传。它不是把整个arXiv收进来，也不是直接远程查询一个全文向量库。

现有“arXiv补证据”只为一次问答临时获取原文，不自动持久加入论文库。本轮只实现PDF上传入库，尚未增加arXiv链接导入入口。

## 尚未覆盖

- 现为本机单用户、macOS实测；导入互斥使用fcntl，Windows适配尚未做，不能声称跨平台即装即用。
- 本地模型需事先安装/缓存；入库没有调用回答API，不等于无需下载向量模型。当前离线模式缺模型时会明确失败。
- 仍依赖已有基线知识库；GitHub全新克隆的首次建库/安装引导、演示资产许可与仓库整体密钥审计属于后续交付工作。
- 标题提取、双栏解析是启发式；扫描件无OCR。删除/回退UI、磁盘配额清理、多人账户和公网部署未实现。
